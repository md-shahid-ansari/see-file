# Security Policy

## Reporting a Vulnerability

Security is important to the SeeFile project. We appreciate responsible reports that help keep the application and its users safe.

If you discover a potential security vulnerability, please **do not publish it in a public GitHub issue or discussion**.

Instead, contact the project maintainer privately through the contact options available on the [SeeFile GitHub repository](https://github.com/md-shahid-ansari/see-file).

Please include as much of the following information as possible:

- A clear description of the vulnerability.
- The affected feature, file, or component.
- Steps to reproduce the issue.
- The potential security impact.
- Screenshots, logs, or a proof of concept, if safe to share.
- Any suggested mitigation or fix.

Do not include real users' private documents, personal information, passwords, or other sensitive data in your report.

## What to Expect

After receiving a report, the maintainer will:

1. Review the reported issue.
2. Assess its severity and potential impact.
3. Investigate and work on an appropriate fix where necessary.
4. Communicate with the reporter when possible.
5. Coordinate disclosure after a fix is available, where appropriate.

Please allow reasonable time for investigation before publicly disclosing a vulnerability.

## Supported Versions

Security fixes will generally be prioritized for the latest version of SeeFile.

Older versions may not receive security updates.

## Security Considerations

SeeFile is designed to process supported documents locally in the browser rather than uploading them to a SeeFile server.

However, local processing does not eliminate all security risks. Users should:

- Use an up-to-date browser.
- Avoid opening documents from untrusted sources.
- Keep their browser and operating system updated.
- Understand that third-party document-processing libraries may have their own security vulnerabilities.
- Avoid assuming that every document format or file is completely safe to open.

SeeFile is provided under its open-source license without a guarantee that every security risk has been eliminated.

## Responsible Disclosure

We appreciate security researchers and users who help improve SeeFile.

Please report vulnerabilities responsibly and give the maintainers a reasonable opportunity to investigate and address them before sharing technical details publicly.

Thank you for helping make SeeFile safer.
